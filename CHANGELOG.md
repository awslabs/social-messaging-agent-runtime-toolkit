# Changelog

All notable changes to SMART, the Social Messaging Agent Runtime Toolkit, are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions are calendar-based, `YYYY.MM.patch`, so `2026.10` is the release line of October 2026, `2026.10.0` is its first release, and `2026.10.1` would be a fix to it; the version lives in the `VERSION` file at the repository root and nowhere else. The admin console has its own heading under each release because a console-only release is a real case.

## [Unreleased]

### Changed
- The Release workflow also publishes a patch release tagged on its line's release branch (`v2026.11.1` on `release/2026.11`), which has the same protection as `main`; a tag on any other branch, or on another line's release branch, is still refused (#140).
- The per-user schedule cap fails closed: when the agent runtime cannot list a user's schedules to count them, `scheduler.schedule` raises `ScheduleLimitExceeded` and creates nothing, instead of counting 0 and creating the schedule (#94). `docs/events-scheduling.md` now describes the cap. Existing projects pick this up with `socialagent runtime update`.

### Fixed
- `scripts/e2e_test.py` checks a reminder by the schedule the turn creates for the test phone, read back from EventBridge Scheduler, instead of English words in the reply. A Spanish reply such as `personal-assistant`'s ("Listo, te recordaré en 5 minutos…") failed the check although the reminder was scheduled, and an English reply that promised a reminder passed it without one. The script now needs `scheduler:ListSchedules` besides `bedrock-agentcore:InvokeAgentRuntime`.
- A phone number quoted in an exception that OpenTelemetry records on a span in the agent runtime is now masked. `record_exception` (which `start_as_current_span` and `use_span` call, and Strands calls itself) wrote the exception's text and traceback into the span's `exception` event, and the error status carried `"<Type>: <text>"`; under ADOT, with Transaction Search on, every span goes to CloudWatch Logs. Importing `socialagent_runtime` now installs `install_span_masking()`, which masks `exception.message`, `exception.stacktrace`, the caller's string attributes (each string in a list or other sequence attribute too) and the status description on the SDK's `Span` before the span ends, for any framework. It reaches an existing project only when its vendored `socialagent_runtime/` is replaced (`socialagent runtime update`) (#226).
- `state.get` returns `None` for an item whose `ttl` has passed, instead of the old value until DynamoDB's background sweep deletes it, which can take days. Agent-side `list_keys` and `list_items` skip such an item too, so they agree with `get`; `delete_prefix` still deletes it. `claim_once` (agent and Lambda side) and `compare_and_set` treat such an item as absent too: an expired `claim#` marker or value no longer refuses a new claim or `expected=None`, and an expired value never matches `expected`. The Lambda-side fix reaches a stack with the next deploy; the agent-side fix reaches an existing project only when its vendored `socialagent_runtime/` is replaced (`socialagent runtime update`). Only a Number `ttl` counts, as with DynamoDB's TTL: an item whose `ttl` is a String or a Boolean never expires and reads as live everywhere (#56, #218).
- An exception that escapes a Lambda handler no longer carries a phone number unmasked into the Lambda runtime's `[ERROR]` line, the invocation's error response or the DLQ's `ErrorMessage`. The Lambda runtime prints it itself, not through `logging`, so the record factory never saw it. Each handler's entry point now masks the exception's text in place before it escapes, a number passed as an argument included wherever the text quotes it, even written with spaces, and so are the notes `add_note` attached; its type, so retry decisions and `isinstance` checks, and its traceback are unchanged. An exception whose text does not come from its arguments (a `FileNotFoundError` with a filename, an `ExceptionGroup`, a custom `__str__`), or whose masked arguments no longer print or cannot be assigned, escapes instead as a `MaskedHandlerError` whose text names the original type, with such a number masked too, and which carries no unmasked original as its `__context__`, so `errorType` changes for it in the `[ERROR]` line, the error response and the X-Ray fault. The escaping text gets `mask_phone`'s five-or-more-digit cut too, as log lines do: an account id in an ARN reads `...9012`, and so does a numeric error code of five or more digits, such as one of Meta's WhatsApp error codes, in what synchronous callers read (the admin console's send-failure reason, `upload_media`'s `RuntimeError`), the DLQ's `ErrorMessage` and X-Ray. This is Lambda-side only and reaches a stack with the next deploy (#212).
- A stack's first `socialagent deploy` no longer fails when CodeBuild tries the Lambda layer, agent image, zip package or template sync build before IAM has applied the service role's new policy. Such a build fails in `QUEUED` with `CLIENT_ERROR` and runs nothing; the apply now starts it again, up to six times in all with a growing pause, and still fails at once on a build that ran and failed. `infra-terraform/README.md` also says how to recover from the AWS provider's rare `EntityAlreadyExists` on a role it created itself (#211).
- A phone number quoted in an exception's text or traceback is now masked in every log record the SDK's processes write through `logging`. Importing `socialagent` (the Lambdas and blueprint handlers) or `socialagent_runtime` (the agent) installs a log record factory, `install_log_masking()`, that puts every log record through `mask_phone` before any handler sees it: the message, the traceback (chained exceptions included) and the stack. Lines that log a traceback keep it, masked, under a standard `logging.Formatter`, the Lambdas' text log format. OpenTelemetry's `LoggingHandler` (ADOT in the agent runtime) reads only `exc_info`, so the factory also sets the record's `exception.type`, `exception.message` and `exception.stacktrace` attributes, masked, which it exports; a formatter that reads `exc_info` itself, such as `bedrock_agentcore`'s `RequestContextFormatter`, now gets no exception. The factory also cuts every other run of five or more digits in a log line, such as an account id in an ARN, to its last four, and `mask_phone` does not cut a number an error writes with spaces or dashes inside a sentence. The Lambda-side change reaches a stack with the next deploy, `personal-assistant` handlers included, with no edit; the agent-side change reaches an existing project only when its vendored `socialagent_runtime/` is replaced (`socialagent runtime update`) (#92).
- `project` (and `project_name` in Terraform, and the name `socialagent init` takes) accepts at most 27 characters, down from 35. Each per-stack S3 bucket is named `<environment>-<project>-<purpose>-<account id>`, and S3 allows 63 characters, so a longer name passed every check and then failed at `apply` on the bucket, part way through creating the stack, unless shared buckets were set: from 28 characters with `test` or `prod` (29 with `dev`) on `conversation-logs`, the longest. A stack whose name is 28 to 35 characters deployed only with `shared_runtime_bucket` set (and, from 32 characters, `shared_artifacts_bucket`), and `deploy` now refuses its name; renaming a stack replaces every resource, so such a stack stays on an earlier SDK until it is recreated under a shorter name. `tests/test_resource_name_lengths.py` rebuilds each resource name the stack's `.tf` files write from the longest environment and project name and checks it against that service's limit, and fails on a resource type or name attribute it has no limit for (#246).

### Security
- The agent runtime no longer logs the content of each Bedrock call. AgentCore Runtime turns on agent observability, under which `aws-opentelemetry-distro` set `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` to `true`, and the Bedrock instrumentation wrote every model call's whole request (the system prompt, the restored history, tool inputs and results, image and document bytes) and its reply to the runtime's log group. The stack now sets it to `false` on the runtime, and `agent.environment` sets it back. Strands' own record of each turn stays, for AgentCore Evaluations and the GenAI Observability prompt views ([The agent runtime's log group](docs/configuration.md#the-agent-runtimes-log-group)).
- The agent runtime's log group, which AgentCore creates with no retention and no data protection, keeps its events 30 days, like the Lambda log groups, and with `enable_pii_log_protection` on (the default) gets their data protection policy, plus custom identifiers for a number with a leading `+`, of any country (`+52` included), in the usual formats (spaces, dots, hyphens or parentheses between the groups), for a national number written in groups (two or three digits, then three or four, then four), and for the conversation's and a scheduled task's session ids and the schedule ids the runtime generates, which hold the user's number. A bare run of digits without a `+` stays readable, because it cannot be told from a timestamp or an id. A deploy creates the group with the AWS CLI if AgentCore has not, then sets its retention. `minimal-deploy-policy.json` adds the data protection actions, which the Lambda groups' policy already needed.
- Both reach a stack at its next `socialagent deploy`, with no `socialagent runtime update`: they are Terraform and the runtime's environment, not the vendored runtime. That deploy deletes the group's events older than 30 days (CloudWatch removes them within 72 hours) and masks only the events ingested after it. A runtime session that started before it keeps logging the Bedrock-call content until it ends, after 15 idle minutes or at most 8 hours.

## [2026.11.0] - 2026-11-13

**Upgrading a project.** The agent runtime changed in this release (outbound reactions), and a project's `socialagent_runtime/` is a copy made by `socialagent init`, so it keeps the old one until it is replaced. A CLI installed from PyPI has no git history to tell an earlier copy from a later or edited one, so `socialagent runtime status` reports the copy as `unknown` and `socialagent runtime update` refuses it: run `socialagent runtime update --force`, which keeps a backup under `.socialagent/runtime-backups/`.

### WhatsApp channel
- Outbound reactions: `messages.reaction(message_id, emoji)` queues an emoji on a user message through the in-band notify path (empty emoji removes a reaction). Existing projects pick this up with `socialagent runtime update`.

### Changed
- The deployment marker's description ends with the solution version, `(vX.Y.Z)`, so the anonymous deployment count can be broken down by release (#105).

### Added
- The `smart-socialagent` wheel ships the stack's Terraform (`infra-terraform/` with `bootstrap/` and `modules/`; not `tftest/`, state, tfvars, lock files or `.terraform/`). Outside a SMART checkout, the CLI copies it into the project's `.socialagent/infra/` and replaces the copy whenever its content differs from what the CLI ships, so edits there are overwritten; Terraform's local state in it (`bootstrap`'s) is kept, across CLI upgrades too. A refresh deletes files, so the CLI refuses a `.socialagent/` or `.socialagent/infra/` that is a symlink. Every command that runs Terraform or reads its variables resolves the root the same way: `--tf-dir`, then the nearest SMART checkout's `infra-terraform/` (unchanged for contributors; a checkout is an `infra-terraform/main.tf` with `pyproject.toml` and `src/socialagent/` beside it, so another repository's `infra-terraform/` above the project is passed over), then that copy. From a pip install, `bootstrap`, `status --refresh`, `config sync` and `config tfvars` work without a checkout; `deploy` and `destroy` refuse the copy with a clear error, because the Lambda layer is still built from the checkout's SDK source, which a later release changes ([#133](https://github.com/awslabs/social-messaging-agent-runtime-toolkit/issues/133)).
- `bootstrap` (when the backend is missing), `deploy`, `destroy`, `status --refresh` and `config sync` check that `terraform` is on `PATH` before they run anything, and `deploy` (except `--plan`) that the `aws` CLI Terraform's provisioners call is too, naming what is missing, instead of failing at the first call or, for `aws`, partway through an apply.

### Fixed
- CLI output, including the anonymous deployment counter notice, stays ahead of Terraform output when redirected to a file or pipe.
- `personal-assistant` now passes `transcribe_languages` to the transcription call in its `on_media` hook, so the setting applies to its voice notes as it does to the default path. `handlers/` is project code, so an existing project adds `language_options=config.transcribe_languages,` to the `transcribe_audio` call in `handlers/webhook.py` by hand. The blueprint's YAML sets `transcribe_languages: [es-MX, en-US]`, which had no effect on its voice notes before this fix, so check that the list names your users' languages before you deploy the change.
- The zip-mode agent archive leaves out the project's `infrastructure/` directory, like the Docker-mode archive. A zip-mode project with that directory gets a new archive hash, so its next deploy rebuilds the package once.
- An upgraded stack now takes the new marker description: the marker parameter's description carries the version, so each release is a resource change CloudFormation applies, instead of a description-only change it ignores and Terraform plans again on every deploy (#68).
- `socialagent templates validate` exits 0 with a message in a project with no `templates.yaml` and no templates path configured, such as one from the `minimal` blueprint, instead of failing. A configured path that is missing, a `templates.yaml` that is a directory or a broken symlink, and a run outside any project are still errors (#83).

### Admin console
- The State tab and the global State page no longer list or count the scheduler's `_schedule#` firing records as user state; Nuclear reset leaves them in place, as they expire on their own.
- "Delete selected" on the State tab and the global State page asks for confirmation, naming how many keys, users and stacks it will delete and warning that the deletion cannot be undone; one click no longer deletes.
- The conversation viewer's "Delete conversation" asks for confirmation inside the viewer, naming the conversation and warning that the deletion cannot be undone, before it deletes the conversation's AgentCore Memory events; one click no longer deletes.
- The Stack Detail Deploys tab reports a failed CodeBuild read instead of showing an empty history, reads each stack's builds in the stack's own region, and reads a zip stack's builds from `<prefix>-agent-zip-build`.
- The Stack Detail header, the Overview's "Last deploy" column and the Stacks page's "Last deploy" column read the last deploy from the stack's own CodeBuild project, so a zip stack or a stack deployed in another region no longer shows "-" where it was deployed.

### Developer experience
- Published on PyPI as `smart-socialagent` ([ADR-0008](docs/adr/0008-pypi-distribution-name.md)): `socialagent` collides with an existing project there. The command and the import package stay `socialagent`, and `deploy` and `destroy` still need a clone of the repository, for the SDK source the Lambda layer is built from: the package ships the stack's Terraform, so `bootstrap`, `status --refresh` and `config` work without one. The package page (`PYPI.md`) opens with the beta and "AS IS" notice.
- A Release workflow publishes to PyPI from a GitHub Release, through trusted publishing and a `pypi` environment with required reviewers; `CONTRIBUTING.md` has the steps.

## [2026.10.0] - 2026-11-05

The first public release. Everything below was in the toolkit when it was published.

### WhatsApp channel
- Outbound message types: text, buttons, list menus, image, document, audio, video, sticker, location, location request, CTA URL, address request, call button.
- Inbound text, media, interactive replies (button, list row, form) and the typing indicator.
- Audio transcription on inbound voice notes.
- Templates: body-only templates in the UTILITY, MARKETING and AUTHENTICATION categories, synced on deploy, with local validation of the rejection causes Meta publishes; a rejection fails the deploy.
- Message buffering: rapid inbound messages are debounced into one agent turn.
- A per-user rate limit, when the state table is enabled.

### Agent runtime
- Recurring and one-shot schedules owned by phone, with ownership read from one field of the schedule name, restricted operation names, a cron floor and a per-user cap.
- External events through API Gateway with an API key and a secret, with credentials sent only to this account's API bound to the key.

### Developer experience
- The `socialagent` CLI: `init`, `dev`, `recipe`, `templates`, `config`, `bootstrap`, `deploy`, `destroy`, `status`, `secrets`.
- Three blueprints (`minimal`, `personal-assistant`, `appointment-scheduler`) and three recipes (`rich-messages`, `voice-reply`, `generate-image`), copied into a project as files.

### Operations
- Security review follow-ups: the SNS certificate URL is parsed, not matched; the WhatsApp envelope is pinned; media roots are allowlisted; invocation logs carry metadata only; roles are scoped to the stack's media keys; console authorization is single-layered.
- Dependabot with cooldowns on every ecosystem: pip, npm, GitHub Actions, Terraform.
- An anonymous deployment counter: one CloudFormation marker stack per deployment, stated in the README and printed by `socialagent deploy`, and turned off with `terraform.enable_deployment_metrics: false`.
- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `NOTICE`, and Apache-2.0 license headers on every file.

### Admin console (beta)
- Fleet view, conversations, per-user state, schedules, templates with preview, logs, errors, restart, phone binding; Cognito sign-in with MFA; deny-by-default authorization on every route. The console has had less production time than the SDK and CLI and ships as beta; it is a separate Terraform root an adopter may skip.
